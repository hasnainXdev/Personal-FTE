## Log Format

Each action log entry follows this format:

```markdown
## MCP Action Log Entry

**Timestamp**: ISO8601
**Action**: action_type
**Request**:
```json
{
  "action": "...",
  "parameters": {...}
}
```
**Response**:
```json
{
  "success": true/false,
  "result": {...},
  "error": "..."
}
```
**Status**: success | failure
**Duration**: milliseconds
**Plan Reference**: Plans/Plan_YYYYMMDD_NN.md (if applicable)
**Approval Reference**: Proposed_Actions/Action_YYYYMMDD_NN.md (if applicable)
```

## Action Types

### Email Actions
- `send_email`: Send email via SMTP

### LinkedIn Actions
- `post_linkedin`: Publish post to LinkedIn

### Webhook Actions
- `fetch_url`: HTTP GET/POST request
- `trigger_webhook`: Send webhook payload

---

## Error Codes

| Error Code | Description |
|------------|-------------|
| INVALID_REQUEST | Request validation failed |
| ACTION_NOT_FOUND | Action type not registered |
| AUTH_FAILED | Authentication/authorization failed |
| TIMEOUT | Action timed out |
| RATE_LIMITED | API rate limit exceeded |
| INTERNAL_ERROR | Server internal error |
| SERVICE_UNAVAILABLE | External service unavailable |

---

## Maintenance

- Log is append-only (no edits after creation)
- Sensitive data (passwords, tokens) is redacted
- Failed actions include error_context
- Log file should be backed up regularly
